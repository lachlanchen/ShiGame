# Audio direction — rain, distance, consequence

Status: implemented engineering vertical slice · human listening required · 2026-08-09

SHI should sound restrained, material and legible. Chapter I begins inside rain, mud, reed marsh and a frightened human network—not inside a heroic score. Audio supports attention and consequence; it does not announce historical authenticity, decorate every gesture, or turn the player’s decisions into arcade rewards.

## Chapter I identity

The first sound layer is a low, filtered rain bed. It provides continuity across the Daze Village council while leaving speech-frequency space available for future voice work. Short tonal cues form a small interaction language:

| Event | Meaning | Shape |
| --- | --- | --- |
| Select | focus moved to another viable order | very short rising sine |
| Inspect | wartable intelligence changed | quiet, slightly longer triangle |
| Drawer / close | a reference layer opened or closed | reciprocal rise/fall |
| Commit | an order became irreversible | two low, overlapping strokes |
| Ending | the network survived the chapter | two separated rising tones |
| Failure | pursuit or dispersal closed the network | one slow descending tone |

These cues are semantic but redundant. Focus, map state, consequence, completion and failure remain fully expressed through text, geometry, focus and `aria-live` status. A player who disables sound loses no information.

## Shared production contract

[`content/audio/chapter-01-audio.json`](../../content/audio/chapter-01-audio.json) is the versioned source of truth for Web Audio, Unreal and Unity. It defines:

- opt-in defaults, independent ambience/effects values, conservative bus caps and fades;
- a seeded eight-second procedural rain loop and filter band;
- the exact cue names, shared linear oscillator envelopes, frequencies and gains;
- a deterministic 18-second reference programme, a visible-browser capture programme and enforceable peak/loudness/DC/loop/channel limits;
- only `sine` and `triangle` oscillators, so client parity remains practical and reviewable.

The Web, Unreal and Unity copies are generated by `npm run sync:content`; `npm run validate:audio` rejects stale copies, unsafe ranges, undocumented cue drift, non-opt-in startup or provenance weakening. Runtime implementations may use native engine primitives, but must not invent extra authored cues outside the contract. Unreal parses and validates this contract in C++, reconstructs rain/cues through a modern `ISoundGenerator`, exposes an opt-in Slate mixer and passes the official UE 5.8.1 procedural-contract automation. Native audio-device capture and human listening evidence remain open.

## Objective engineering evidence

The contract is measured through two distinct paths. `npm run render:audio-reference` reconstructs every cue and the filtered rain bed at 48 kHz, writes an ignored 24-bit WAV, runs FFmpeg EBU R128/sample analysis, and regenerates the committed machine report and spectrogram. `npm run capture:web-audio` launches a separate visible Chrome desktop, routes only that browser into a dedicated PipeWire sink, proves two seconds of pre-consent silence, then records sixteen seconds of actual Web Audio while real UI actions trigger six cues.

FFmpeg and FFprobe are production build tools, not shipped runtime dependencies. The scripts prefer the system `/usr/bin` tools when present, otherwise resolve through `PATH`; `SHI_FFMPEG` and `SHI_FFPROBE` may identify reviewed alternate binaries. This avoids an obsolete Conda binary shadowing the workstation's measured FFmpeg. GitHub validation and Pages jobs install the tools explicitly, and every reference report records the actual FFmpeg version used.

| Programme | Integrated | True peak | Sample peak | DC | Channels | Result |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Deterministic reference | −36.7 LUFS | −23.0 dBTP | −22.96 dBFS | 0.00000028 | exact dual mono | pass |
| Public visible Chrome runtime | −35.7 LUFS | −22.4 dBTP | −22.49 dBFS | 0.00000021 | exact dual mono | pass |
| Pre-consent Chrome | silence | −∞ | −∞ | 0 | exact dual mono | pass |

The authored window is −45 to −24 LUFS, no more than −12 dBFS sample peak or −10 dBTP true peak, and no more than 0.001 absolute DC. The raw deterministic rain is zero-mean; its loop-boundary jump is 0.6029 of its ordinary 99th-percentile adjacent transient, below the 0.8 ceiling. Every one of the seven reference cues exceeds the −42 dBFS audibility floor. Reports and spectrograms live in [`docs/production/evidence`](../production/evidence/); reproducible WAVs stay under ignored `.runtime/audio/` and are never packaged.

The first real-browser recording was intentionally rejected: it measured a −4.7 dBTP startup burst. Inspection traced this to a Web Audio automation fade beginning at the `GainNode` intrinsic full-scale value. The engine now pins the initial mute directly, uses `cancelAndHoldAtTime` for subsequent fades, and has a regression test. A fresh visible capture removed the burst and passed all eight browser-audio checks. This is why runtime capture is a separate gate from mathematical reference rendering.

## Rights and provenance

No recording, sample library, generated song or external media is present. The ambience and cues are reconstructed at runtime from project-authored numbers and deterministic source code. The asset record is [`assets/provenance/chapter-01-audio.json`](../../assets/provenance/chapter-01-audio.json). This makes the rights boundary clear; it does not make the audio release-ready.

The rain is an expressive sound design layer, not evidence about the exact weather, acoustic environment or instruments of 209 BCE. Later historical instruments, work songs, military signals and voices require separate source research, cultural review, recording/generation provenance and explicit approval before they enter a build.

## Mix and accessibility contract

- Sound starts off and can only begin after a player gesture.
- Ambience and effects have independent persistent controls. Speech and music buses are not shown until those content categories exist.
- Master gain and per-bus gain are capped in the shared contract; individual cue gains are capped again.
- Opening the mixer, enabling sound, changing volume and previewing a cue are keyboard/touch accessible. Values have visible percentages and localized names.
- No analytics, microphone, remote request or media autoplay is involved.
- Reduced motion does not automatically silence audio; these are separate player preferences.
- A future voiced build must preserve dialogue history, captions and independent speech control before release.

## Review gates

Engineering now verifies deterministic samples, configuration parity, measured reference output, measured visible-browser output, exact pre-consent silence, runtime state, persistence and absence of remote traffic. It cannot honestly certify listening quality. Before public-alpha audio is signed off, reviewers must complete:

- reference headphones, laptop speakers, phone speakers and a low-volume environment;
- mono fold-down, repeated-loop seam and rapid-input fatigue checks;
- perceptual confirmation that the measured peak, true-peak and programme-loudness target is appropriate on release devices;
- auditory accessibility and sensory-load review, including whether rain masks cognition;
- Web/Unreal/Unity perceptual parity and pause/background/resume behaviour;
- native review in every supported release platform.

Until those sessions are recorded, the release checklist audio box stays open.
